Skyward 0.2.6 for the Xiaomi 15 Pro (`haotian`), made on the stock recovery
`OS4.0.0.19.XOBCNXM`.

Image: `skyward-v0.2.6-haotian-OS4.0.0.19.XOBCNXM.img`. Check it against
`SHA256SUMS`, then, with the phone in fastboot mode on the slot it runs from:

```sh
sha256sum --check SHA256SUMS
fastboot flash recovery skyward-v0.2.6-haotian-OS4.0.0.19.XOBCNXM.img
fastboot reboot recovery
```

## 这次新增的功能

### 1. 在手机上直接改 AVB 校验

**高级 → AVB 校验**。两个开关各管一项：

| 校验 | 作用 |
| --- | --- |
| 启动验证 | 引导器在启动前校验各分区的签名 |
| dm-verity | 读取分区时逐块校验内容 |

关闭任意一项都要**滑动确认**；改动只写入手机当前槽位的 `vbmeta`，重启后生效。
写入前会把原镜像备份到 `/tmp`，写入后再读回来比对；如果这期间分区内容变了
（例如正在刷 zip），改动会被拒绝而不是覆盖掉更新的镜像。**bootloader 未解锁时
不提供任何写入**。

### 2. 刷入 ROM 后自动禁用 AVB

**安装页 → 选项**里的开关，默认关闭。

这一项由 recovery 自己做，**不依赖刷机包**：安装脚本是任意程序，可能根本不会调用
`avbctl`；而用非本机密钥签名的 ROM 在仍然校验签名的 bootloader 上根本起不来。所以
脚本正常结束、或系统更新装好后，两项校验会在**手机下次启动所用的槽位**里被关闭。

由系统请求的安装（无人在屏幕前确认）永远不会做这件事。AVB 写入失败**不会**让已经
完成的安装变成失败——它会在屏幕上和内核日志里说明，事后仍可在 AVB 页手动关闭。

### 3. 记住解密 data 的密码

**设置 → 解密**里的开关，默认关闭。

开启后，成功打开 data 分区的那个密码会被保存，下次进入 recovery 时自动尝试。
存储方式：

- 用 AES-GCM 加密，密钥由**本机序列号**派生，写入 `/metadata/skyward/credential`
- **绝不写入 settings.json**——拷走设置文件不会带走密码
- 拷到另一台手机上**解不开**
- 关闭开关会**删除**该文件

**它防什么、不防什么**：密钥不在 TEE 里（recovery 无法让安全世界加密它从未见过的
密钥），所以它能防住「把文件拷走」，**防不住拿着这台手机的人**——对方可以运行同样的
代码。这是默认关闭的原因，也是设置页写明的代价。

## 界面

- **AVB 校验页两个卡片之间补上了间距**，不再贴在一起。

## 怎么确认装上了

```sh
adb shell dmesg | grep -i "recovery up"   # 应为 haotian 0.2.6
```

## This release in English

**AVB from the phone.** Advanced → AVB verification gives each check its own
switch: boot verification (the bootloader checking signatures) and dm-verity
(checking blocks as they are read). Every change needs the swipe, writes only
the running slot's `vbmeta`, keeps the image as it was in `/tmp` first, reads it
back afterwards, and refuses if the partition changed in between — so a page
left open while a zip flashes cannot overwrite a newer image. A locked
bootloader gets no write controls at all.

**AVB after a ROM is installed.** A switch on the Install page, off by default.
It is the recovery's own act rather than the package's: an install script is an
arbitrary program that may never call `avbctl`, and a ROM signed with other keys
will not start on a bootloader that still checks. After a clean script or a
finished update, both checks are turned off in the slot the phone starts from
next — never for an install the system asked for, and a failed write never turns
a finished install into a failed one.

**Remembering the decrypt password.** Off by default. On, the credential that
opened the owner's files is sealed with AES-GCM under a key derived from the
phone's serial, kept at `/metadata/skyward/credential`, and tried by itself at
the next start. It is never written to the settings file, a copy taken to
another phone opens nothing, and turning the switch off deletes it. It does not
defend against someone holding this phone — the key is not in the secure world,
because a recovery cannot make the secure world encrypt a secret it has never
seen — and that is why it ships off and says so where it is offered.

**Interface.** The AVB page's two cards have the gap between them that every
other page leaves.
