Skyward 0.1.4 for the Xiaomi 15 Pro (`haotian`), made on the stock recovery
`OS4.0.0.19.XOBCNXM`.

Image: `skyward-v0.1.4-haotian-OS4.0.0.19.XOBCNXM.img`. Check it against
`SHA256SUMS`, then, with the phone in fastboot mode on the slot it runs from:

```sh
sha256sum --check SHA256SUMS
fastboot flash recovery skyward-v0.1.4-haotian-OS4.0.0.19.XOBCNXM.img
fastboot reboot recovery
```

## 这次修的内容

- **屏幕偏色**。这台手机的面板是 pentile 排列、子像素渲染交给显示控制器做，
  面板在 capabilities 里报 `spr_pack_type=pentile`。recovery 现在按这份报告写
  `drm_msm_spr_init_cfg` 到 CRTC 的 `SDE_SPR_INIT_CFG_V2`（上游 `d7fefd7`）。
  之前红色和蓝色在屏幕上被平均成了紫色，现在各自走各自的子像素。
- **连接器与平面的颜色属性不再强写**。`bpp_mode`、`frame_trigger_mode`、
  `COLOR_ENCODING`、`COLOR_RANGE` 都不再设置，交给驱动按开机时告诉它的面板自己
  决定——手机自带的 recovery 也是这么做的；只有本来就需要的 `dsc_mode` 还留着。
- **VINTF 描述写最低版本**。`servicemanager` 只要有一个描述解析不了就把整份清单
  丢掉，于是密钥服务一个也起不来、界面停在第一屏。现在发布的描述统一写
  `version="1.0"`，也就是 recovery 里这份 `libvintf` 认识的最低版本。
- **服务的监听 socket 能到它该到的程序里**。此前描述符是 close-on-exec 复制
  的，却没人清掉这个位，exec 时就被关掉了：`hlosminkdaemon` 因此每五秒退出
  重来一次。现在在子进程 exec 之前单独清掉。
- 合并上游 0.1.3：挂载点的修复、`kms` 报告里显示面板能力等。

## 怎么确认装上了

`adb shell dmesg | grep "the display is"` 应该出现

```
skyward: the display is DSI connector 67 mode "1440x3200x120cmd" 1440x3200 120 Hz,
… link dsc_mode=1,bpp_mode=0,frame_trigger_mode=2,
sub-pixel rendering SDE_SPR_INIT_CFG_V2, 304 bytes held
```

`skyward: /vendor/bin/hlosminkdaemon: pid N ended` 不再每五秒重复。

## This release in English

The subpixel rendering that this panel leaves to the display controller is now
set up from the panel's own `spr_pack_type=pentile` capability (upstream
`d7fefd7`), the connector and plane colour properties are no longer forced,
every VINTF description names `version="1.0"` so `servicemanager` keeps the
manifest and the credential services come up, and the listening sockets a
service is started with are handed to it across the exec. Also merges upstream
0.1.3.
