## 这次修的内容

修的是 0.2.3 里的一个回归：**关掉息屏显示后，双击唤醒失效了。**

原因是触摸屏跟着面板一起断电。在手机上量到的内核日志：

```
[MI_TP_I][xiaomi_drm_panel_notifier_callback:827]: FB_BLANK POWER DOWN
[MI_TP_I][xiaomi_touch_suspend_work:673]: touch id 0 enter
```

从这条通知开始，`/dev/input/event7` 在面板黑着的时候**一个事件都不报**，
面板亮起来才恢复。触摸设备是小米触摸层做出来的虚拟节点
（`Xiaomi_Touch_Input_0`），硬件挂在 `spi2.0` / `synaptics_tcm_spi` 上，
两者都**没有 `power/wakeup`**，所以注册唤醒源这条路在这个面板上走不通；
`/sys/kernel/debug/tp_debug/switch_state` 虽然接受 `irq-enable` 和
`tp-suspend-off`（写入都返回成功），IC 仍然不报，驱动会在下一条面板通知里
重新把它挂起。

这解释了为什么之前双击是好的：**息屏显示走的是面板自己的 doze —— 用 DCS
命令集让面板进入低功耗，CRTC 一直在跑，根本不发 `FB_BLANK`，触摸 IC 因此
从未被挂起。** 而 0.2.3 把息屏显示关掉之后，面板走的是
`rest()`/`turn_off()`，那两条都会发 `FB_BLANK`，顺带把触摸屏也关掉了。

所以现在：**要点亮双击的手机，面板保持「doze 黑屏」而不是彻底断电。**
用的是和息屏显示同一套命令集，只是先把画面涂黑，然后就不动了。代价是这个
状态下手机不会休眠——这是这块面板上双击的实价，现在明明白白写在代码和
`AGENT.md` 里，而不是当成免费的。如果哪天换个触摸驱动真的有唤醒源，
`arm_wakeup` 会成功，那条路会照旧把面板彻底关掉。

## 怎么确认装上了

`adb shell dmesg | grep -i "recovery up"` 应出现

```
skyward: haotian 0.2.4 recovery up, …
```

最直接的验证是这条，黑屏时也应该一直是 0：

```sh
adb shell "dmesg | grep -c FB_BLANK"    # 0 = 面板没有断电，双击能用
```

黑屏时点一下屏幕，`adb shell "timeout 5 getevent /dev/input/event7"` 应该能看到事件。

## This release in English

A regression in 0.2.3: **turning the always-on display off broke the two-tap
wake.**

The touchscreen dies with the panel. Xiaomi's touch driver suspends the touch IC
on the display's blanking notice (`FB_BLANK POWER DOWN` →
`xiaomi_touch_suspend_work`), and from then on `/dev/input/event7` reports
nothing at all while the panel is dark. The input node is a virtual one made by
Xiaomi's touch layer and the hardware is `spi2.0` on `synaptics_tcm_spi`; neither
has a `power/wakeup`, so arming a wakeup source cannot work on this panel. The
`tp_debug` switches accept `irq-enable` and `tp-suspend-off` and the IC still
reports nothing, because the driver re-suspends it on the next notifier.

That is why the tap worked while the AOD was on: the AOD puts the panel into its
own doze with a DCS command set, the CRTC keeps running, no `FB_BLANK` is sent,
and the touchscreen is never suspended. Turning the AOD off sent the panel
through `rest()`/`turn_off()`, which do blank — and took the touchscreen with
them.

So a phone that has to feel a tap now keeps its panel dozing dark instead of
taking it down: the same command set the AOD uses, with the frame blacked out
first. Such a phone is never off, so it does not suspend either; that is the
real price of a double tap on this panel, and it is stated plainly now rather
than silently assumed. A phone whose driver does expose a wakeup source still
takes the panel down as before.
