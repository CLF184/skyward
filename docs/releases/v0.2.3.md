Skyward 0.2.3 for the Xiaomi 15 Pro (`haotian`), made on the stock recovery
`OS4.0.0.19.XOBCNXM`.

Image: `skyward-v0.2.3-haotian-OS4.0.0.19.XOBCNXM.img`. Check it against
`SHA256SUMS`, then, with the phone in fastboot mode on the slot it runs from:

```sh
sha256sum --check SHA256SUMS
fastboot flash recovery skyward-v0.2.3-haotian-OS4.0.0.19.XOBCNXM.img
fastboot reboot recovery
```

## 这次修的内容

- **锁屏密码只认当前的那个。** 之前改过锁屏密码后，recovery 仍然验证**旧密码**，
  新密码反而不认。原因是 `locksettings.db` 用的是 SQLite 的 WAL 模式，新密码
  所在的记录还留在 `-wal` 日志里，而旧代码以 `?immutable=1` 打开数据库，等于
  告诉 SQLite「这个文件不会变」，于是它只读主文件、**从不重放日志**——读到的
  还是改密码之前的那个 protector，验证的自然也是旧密码。现在把数据库连同
  `-wal`/`-shm` 复制到临时目录，先让 SQLite 把日志合并进副本再读，既不会写
  `/data`，也不要求手机是正常关机（掉电留下的不完整日志同样能读）。
- **息屏后手机真的会休眠了。** 之前因为双击亮屏，`may_sleep` 里带着
  `!double_tap`，`haotian` 在息屏时**永不休眠**，这是功耗高的主要原因。现在
  息屏时先把触摸屏注册成内核唤醒源（`power/wakeup`），再让手机休眠，第一下
  轻点就能唤醒，第二下点亮面板。只有在驱动确实没有唤醒开关时，才退回「息屏
  不睡」的老做法——并在内核日志里说明原因。
- **面板不再切到 120 Hz。** 每次亮屏都切到最快刷新率，而那是一次额外的
  modeset，面板和显示控制器都要为它付功耗。现在由 `[display] fastest_refresh`
  控制，默认关闭，`haotian` 显式写 `false`。面板上电用的模式、DSC 和亚像素
  渲染块都没动——那是修颜色的部分，不能碰。
- **息屏时空转更少。** 息屏且无事可做时，主循环的等待从 1 秒放宽到 5 秒（所有
  fd 仍被 poll，按键、插拔、触摸照样立刻唤醒）；电池从每秒读一次改为息屏时
  每 10 秒读一次，插拔事件仍会立即触发一次读取。
- **AOD 刷入后默认关闭。** 息屏显示（面板自身的 doze）不再默认开启，需要在
  「设置」里手动打开。开关本身还在，功能没有删。
- **刷入后自动清理 ART 缓存。** 新镜像第一次启动时清一次
  `/data/dalvik-cache`、`/data/misc/apexdata/com.android.art/dalvik-cache` 和
  `/data/ota`，让系统按自己的方式重新编译；否则手机跑的是为旧系统编译的代码，
  一边校验一边重编，既慢又热。做过的记录写在 `persist` 的一个几字节文件里，
  所以只做一次，且在数据分区打不开时会留到下次再试，绝不影响启动。

## 怎么确认装上了

`adb shell dmesg | grep -i "recovery up"` 应出现

```
skyward: haotian 0.2.3 recovery up, …
```

另外可以看这几行（第一次启动新镜像时）：

```
what ART compiled is cleared for 0.2.3 …
the touchscreen wakes the phone, so a tap lights the dark panel after it has slept
```

## This release in English

Three fixes, all from the same report.

**The screen lock the phone has now.** After a password change the recovery went
on accepting the *old* one. `locksettings.db` is written in SQLite's
write-ahead log mode, so the newest `sp-handle` can still be in
`locksettings.db-wal`; opening the file with `?immutable=1` tells SQLite it never
changes, so it never replays that log and the recovery read the previous
protector. It is now read from a copy whose log has been folded in, which needs
no write to `/data` and no clean shutdown.

**A phone that sleeps.** `may_sleep` carried `!double_tap`, so this phone never
suspended with the panel off — most of the power draw. The touchscreen is now
armed as a wakeup source before the phone sleeps, so the first tap wakes it and
the second lights the panel; only a driver with no wakeup switch falls back to
staying awake.

**A panel at 60 Hz**, unless `[display] fastest_refresh` asks for more, and a
dimmer idle loop: a 5 s wait with the panel dark, and the battery read every 10 s
instead of every second. The always-on display now ships off. And the first start
of a new image clears what ART compiled ahead of time, once, recorded on
`persist`, so the phone stops running on code built for the system it replaced.
