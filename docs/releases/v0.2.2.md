Skyward 0.2.2 for the Xiaomi 15 Pro (`haotian`), made on the stock recovery
`OS4.0.0.19.XOBCNXM`.

Image: `skyward-v0.2.2-haotian-OS4.0.0.19.XOBCNXM.img`. Check it against
`SHA256SUMS`, then, with the phone in fastboot mode on the slot it runs from:

```sh
sha256sum --check SHA256SUMS
fastboot flash recovery skyward-v0.2.2-haotian-OS4.0.0.19.XOBCNXM.img
fastboot reboot recovery
```

## 这次修的内容

- **recovery 内更新改为看本仓库。** 更新页此前问的是上游的 `kirklin/skyward`，
  那是多机型仓库，会把为别的手机构建的镜像推给这台手机，而本仓库自己的 release
  从来没被查过。现在它只问 `Rinrroy/skyward-for-haotian`。
- **发布产物直接是镜像。** 上游把每台手机的镜像打包成 zip 再发布，代码去 zip 里取；
  本仓库的 CI 直接发布 `.img`。现在按 `.img` 匹配，而 `upgrade::unzip` 两种都认：
  先读 Android 启动镜像的魔数，是镜像就直接收下，否则按单条目 zip 打开。因此
  0.2.1 之前那种 zip 发布和之后直接发布镜像可以互相升级。

这一版是**让更新链真正通到本仓库**的那一版：装了 0.2.2 之后，更新页面对的就是
这个仓库，之后可以直接在 recovery 里更新，不必再刷机。

> 0.2.1 及更早的版本仍会去问上游仓库，所以它们检查不到这个仓库的新版本——
> 需要手动刷一次 0.2.2，之后就能在机内更新了。

## 怎么确认装上了

`adb shell dmesg | grep -i "recovery up"` 应出现

```
skyward: haotian 0.2.2 recovery up, …
```

在「设置 → 更新」里检查一次，能问到 `Rinrroy/skyward-for-haotian` 的最新版本即可。

## This release in English

The recovery now asks **this fork's** repository for its own updates instead of
upstream's multi-device one, which was offering it images built for other
phones. The asset it looks for is the image as this fork publishes it — the
`.img` itself, not the zip upstream wraps it in — and `upgrade::unzip` takes
either, reading the Android boot image magic first and falling back to the
one-entry zip that older releases carried, so a phone on either kind can go to
the other.

This is the release that makes the update chain point here: once 0.2.2 is on the
phone, later versions install from inside the recovery. Versions 0.2.1 and
before still ask upstream and cannot see this repository's releases, so one
manual flash is needed.
