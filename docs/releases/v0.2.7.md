Skyward 0.2.7 for the Xiaomi 15 Pro (`haotian`), made on the stock recovery
`OS4.0.0.19.XOBCNXM`.

Image: `skyward-v0.2.7-haotian-OS4.0.0.19.XOBCNXM.img`. Check it against
`SHA256SUMS`, then, with the phone in fastboot mode on the slot it runs from:

```sh
sha256sum --check SHA256SUMS
fastboot flash recovery skyward-v0.2.7-haotian-OS4.0.0.19.XOBCNXM.img
fastboot reboot recovery
```

## 这次修的内容

**「高级 → AVB 校验」点了没反应。**

那一页画了 7 行，却只给了 6 个动作——最后一行 AVB 校验画出来了、能点、但什么也不做。
`hits` 用 `zip` 按索引配对，多出来的部分被静默丢掉，所以没有任何提示。

修了两处：

- 补上 AVB 行的动作。
- `hits` 现在断言「行数与动作数必须一致」。同类错误以后会在开发阶段直接失败，而不是
  变成一个点了没反应的按钮。
- 顺带让遍历每个页面入口的测试覆盖高级页的**全部** 7 行（原本漏了 Relabel、
  Filesystems、Update 和 Avb）。

上一版（0.2.6）新增的三项功能本身没有问题，只是这一个入口没接上：

- AVB 校验页（读写启动验证与 dm-verity）
- 刷入 ROM 后自动禁用 AVB 的开关
- 记住解密密码

## 怎么确认装上了

```sh
adb shell dmesg | grep -i "recovery up"   # 应为 haotian 0.2.7
```

## This release in English

**Advanced → AVB verification did nothing when touched.** The page drew seven
rows and handed `hits` six actions: the last row was drawn, could be touched,
and had no action at all. `hits` pairs them by index with `zip`, which silently
drops what is left over, so nothing said so.

The row has its action now, and `hits` asserts that a list is given one action
per row — the same mistake now fails while it is being written instead of
becoming a button that does nothing. The test that walks every page's entries
covers all seven rows of the Advanced page; it had been missing Relabel,
Filesystems, Update and Avb.

What 0.2.6 added is unchanged and works once the row is reachable: the AVB page,
the "disable AVB after a ROM is installed" switch, and the remembered decrypt
password.
